# Draft request for a bounded review trial

**Draft only. Not sent.** Recipient role: Assistant Commissioner, M-East ward, with Assistant Engineer (Water Works), M-East. Confirm routing and responsible operator with the office. Role sources and access date: [pilot overview](README.md).

Subject: Request to validate one water-service inspection review using UrbanSaarthi

I am an individual participant preparing UrbanSaarthi for the Seva First Innovation Challenge. The prototype explains settlement priorities, compares explicitly hypothetical interventions and separates physical work completion from a documented service review. Its mapped service indicators are demonstration data. No agency endorsement or measured resident benefit is claimed.

I request a short walkthrough of one existing water-service inspection/closure review and, if useful, a bounded trial on an agreed cluster. The purpose is to test whether a source-linked brief reduces critical evidence omissions or review effort compared with your current process. If the existing system already meets this need, the project should adapt to it or stop.

Could the office identify the competent review owner and actual asset operator, and advise whether a small permitted extract is available? We need current aggregate boundaries/asset identifiers, observation dates, service definitions, work status definitions and de-identified closure evidence. Household names, Aadhaar, phone numbers, income, eligibility records and resident-level coordinates are not requested.

Before any trial, we would agree a consent/observation protocol, data ownership, authorised storage, retention, independent review and a stop rule. We would return a reproducible assessment and a handover cost estimate. Construction, statutory approvals, housing allocation and relocation are outside the software's authority.

Applicant identity and contact details: complete privately before sending.

## Proposed 30-minute walkthrough

1. Identify the actual decision, trigger, owner, existing software and last completed example.
2. Observe how current records, site checks, complaints and service targets are reconciled.
3. Identify one measurable omission or effort problem, including cases already handled well.
4. Agree a fair comparison task and who assesses the result without viewing the prototype score.
5. Confirm operator responsibility, permission, payer and whether there is enough value to proceed.

## Minimum data request

| Input | Requested form | Required provenance |
|---|---|---|
| Agreed study area | Approved aggregate GeoJSON or map extract | Owner, effective date, CRS, permission |
| Public water assets | Stable operator ID, general location, service/ownership type | Source and update date, location disclosure permission |
| Service observations | De-identified measurements and observation windows | Method, units, dates, missingness, reviewer role |
| Work register | Planned/due/completed dates, target, responsible operator | Status definitions, approved reference ID |
| Closure evidence | Redacted inspection records, relevant complaint status | Evidence date, review date, authority |
| Costs | Approved schedule items or current quotations | Quantity, unit, rate date, taxes, scope and exclusions |

Request confirmation that the extract may be used in a competition demonstration. Do not assume government website visibility grants unrestricted reuse.
