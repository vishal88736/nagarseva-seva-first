# Eight-phase checklist and deliverable map

Status describes the actual package on 17 October 2026. **DONE** means the named document/software output exists; it does not turn a proposed pilot into a completed trial. **WEAK** means a material validation dependency remains. **MISSING** means no supporting evidence was obtained.

## Phase 1 — Problem

Do: retain one inspection-review problem in a proposed M/E cluster, label historical evidence and seek a workflow walkthrough. Deliverable: [problem/gap research](../research/research_gap.md), [literature](../research/literature_review.md), [real public-record case](../research/public_record_case.md).

| Item | Status | Gap | Fix |
|---|---|---|---|
| Named geography and sharp review question | DONE | Operational cluster boundary unconfirmed | Agree one permitted boundary with the owner |
| Historical population, housing and WASH evidence | DONE | No current settlement prevalence | Collect proper local observations/denominators |
| Root causes, personas and programme counterevidence | DONE | Personas are provisional, not interviewed | Use the consented validation kit |
| Confirmed reviewer demand | MISSING | No officer/operator comparison | Observe the actual process and an existing report |

Common mistakes: treating 2011 figures as current, equating no private toilet with no toilet, calling programmes uniformly failed, or interpreting listing blanks as delays.

## Phase 2 — Solution

Do: test an evidence brief against existing approaches. Deliverable: [systems comparison](../research/existing_solutions.md), [technical feasibility](../research/technical_feasibility.md), [local prototype](../prototype/README.md).

| Item | Status | Gap | Fix |
|---|---|---|---|
| Value proposition and working evidence workflow | DONE | Local usefulness unvalidated | Compare one authorised task |
| Comparison with PMAY, SRA, MHADA, AMRUT, SBM and grievance tools | DONE | Internal functions/exports not fully exercised | Ask owner for an existing permitted export |
| Maharashtra instrument source review | DONE | Applicability is site/action-specific | Use competent authority review; no automated entitlement |
| Production integration and security | MISSING | No approved APIs, identities or shared-case controls | Scope after trial, with approved responsibilities |

Common mistakes: relabelling GIS as new AI, claiming legacy ISSR is a fifth PMAY-U 2.0 vertical, or promising statutory service guarantees without an applicable notification.

## Phase 3 — Pilot and adoption

Do: obtain an accountable task and records before field work. Deliverable: [30–60–90 day and scale plan](pilot_and_adoption.md), [validation kit](validation_kit.md).

| Item | Status | Gap | Fix |
|---|---|---|---|
| Proposed sponsor, operator roles and trial gates | DONE | No acceptance or asset-specific duty confirmed | Confirm competent owner and contract/MoU |
| Governance, risks and conditional 3–5 year path | DONE | No tested transfer or approved expansion | Validate another operator/ward before scale |
| Actual pilot and community participation | MISSING | No interviews/observations conducted | Consent, lawful data and actual participants required |

Common mistakes: naming an agency as a partner without agreement, counting trial targets as people reached, or promising enforcement the prototype cannot provide.

## Phase 4 — Financial model

Do: replace illustrative rates with quotations and assign recurring costs. Deliverable: [cost note](financial_model.md), editable workbook in `outputs/`.

| Item | Status | Gap | Fix |
|---|---|---|---|
| Editable trial and annual cost arithmetic | DONE | Rates/workload assumptions only | Obtain matching quotations and tax basis |
| Household unit cost and SROI | MISSING | No verified denominator or benefits | Keep unavailable; measure before calculation |
| Funding options and maintenance owner | WEAK | No funding or paying body committed | Secure approved trial scope and recurring allocation |

Common mistakes: calling the prototype free, treating an award ceiling as money secured, or financing an evidence tool through an unsupported housing PPP assumption.

## Phase 5 — Impact and metrics

Do: predefine measurement rules with the trial owner. Deliverable: [impact register](impact_metrics.md), [evaluation plan](../research/evaluation_plan.md).

| Item | Status | Gap | Fix |
|---|---|---|---|
| Baseline/target/method register and inclusion lens | DONE | Operational baselines unmeasured | Independent baseline and voluntary accessible participation |
| Software and authored search checks | DONE | Not field accuracy or general retrieval accuracy | Use independent inputs/questions and reviewer labels |
| Measured resident outcomes and SDG progress | MISSING | No field study | Report alignment only until valid outcomes exist |

Common mistakes: turning code tests into household impact, modelled proximity into service availability, or a convenience sample into ward prevalence.

## Phase 6 — Winning edge

Do: pitch the three features supported by available inputs. Deliverable: [ranked feature decisions](winning_edge_and_audit.md).

| Item | Status | Gap | Fix |
|---|---|---|---|
| Ten effort/impact assessments and three submission features | DONE | Qualitative prioritisation, not tested product demand | Revise after the first workflow comparison |
| Advanced AI, drones and allocation ledger | MISSING | Unnecessary data/governance dependencies | Cut from this deadline scope |

Common mistakes: adding features to conceal missing evidence, training CV without local labels, or claiming blockchain solves tenure or allocation governance.

## Phase 7 — Application and pitch

Do: transfer reviewed answers to the actual form and official template. Deliverable: [answer bank](application_answers.md), [scripts](pitch_scripts.md), [judge questions](judge_questions.md), [deck outline](deck_outline.md), editable deck in `outputs/`.

| Item | Status | Gap | Fix |
|---|---|---|---|
| Draft answers, counts, six slides, scripts and fifteen Q&A | DONE | Draft budgets differ from unknown portal limits | Refit to the authenticated form |
| Official-template visual compliance | WEAK | File link found but download blocked | Applicant downloads template and transfers reviewed content |
| Personal eligibility, identity and final submission | MISSING | Deliberately omitted after applicant said skip | Complete privately in the actual portal |
| Live browser demonstration and timed rehearsal | MISSING | Browser unavailable; delivery not timed | Run browser acceptance and rehearse on presentation device |

Common mistakes: inventing word limits, misrepresenting work-order conditions, submitting unknown personal information or claiming unperformed pilots.

## Phase 8 — Final audit

Do: fix evidence and compliance gaps before adding features. Deliverable: [strict score and five fixes](winning_edge_and_audit.md), [browser acceptance](browser_acceptance.md), [validation record](../research/prototype_validation.md).

| Item | Status | Gap | Fix |
|---|---|---|---|
| Eight-dimension internal score and prioritised fixes | DONE | Internal assessment, not judge feedback | Review after actual validation |
| Engineering/file consistency checks | DONE | Does not establish browser or field success | Preserve the stated validation boundaries |
| Unqualified submission readiness | MISSING | Browser, actual portal/template and external validation gates remain | Complete the specific outstanding checks; do not claim all evidence exists |

Common mistakes: treating a completed document pack as government adoption, hiding unknowns behind zeros, or claiming a reviewer-ready draft is an already submitted application.
