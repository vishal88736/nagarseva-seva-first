# Seva Evidence submission pack

Prepared **17 October 2026** for an individual participant. Personal details are omitted at the applicant's request. No account, application, interview, official pilot or agency endorsement was created.

## Start here

1. Open the [updated standalone prototype](../prototype/dist/standalone.html). Use **Real public-record demonstration** on Overview to inspect the attributed SRA case.
2. Read [competition requirements](competition_requirements.md), including the official-template and portal-access limits.
3. Review [draft application answers and word counts](application_answers.md).
4. Use the [six-slide editable pitch](outputs/seva-evidence-pitch.pptx), [outline](deck_outline.md), [three-minute/elevator scripts](pitch_scripts.md) and [fifteen judge questions](judge_questions.md).
5. Inspect the [editable budget](outputs/pilot-budget.xlsx) with its [assumptions and funding note](financial_model.md).
6. Review [phase checklists](phase_checklists.md) and the [strict audit](winning_edge_and_audit.md).

The presentation follows the six public FAQ sections. **The official template could not be downloaded here**, so its visual requirements have not been checked. Download it from the [official guideline page](https://sevainnovationchallenge.in/guidelines.html) and transfer content if the required layout differs. The answers use explicit draft budgets because authenticated form limits were unavailable. No file is represented as already accepted by the portal.

## What remains external

Browser launch is blocked in this workspace. Actual interaction, responsive layout, downloads and accessibility still need an available browser. A real road network/current service observations are unacquired; the SRA record audit is a genuine but narrower desk demonstration. Officer/resident workflow validation, asset-specific ownership, quotations and a recurring payer remain unconfirmed. Use the prepared materials to obtain those facts rather than claim them as completed.

Identity/domicile/category verification, authenticated field/upload limits, official-template compliance and final submission remain private applicant actions. Do not send identity documents or numbers to this project.

## Reproduction

`python3 prototype/scripts/verify.py` rebuilds the standalone prototype and its software validation report. `python3 submission/scripts/prepare_pack.py` checks answer budgets, required files, local links and delivery archives. Optional browser QA is documented separately. The pack contains no credentials, environment files, private build previews or household records.
